# BizAgent Product Sitemap

## Overview
BizAgent is a hub-and-spoke system for running AI agents across digital products. This repository includes the control plane, agent runtime, and operational tooling.

## Structure
- `agent-runtime/` – OpenAI-compatible tool-calling agent runtime (multi-provider).
- `control-plane/` – Web UI, dispatcher, mail router, hub daemon.
- `agents/` – Per-product agent definitions and mailboxes.
- `scripts/` – Operational scripts (control plane, nightly, pruning, etc.).
- `templates/` – Templates for agent.md, dispatch, NIGHTLY, WEEKLY.
- `tests/` – Integration test suite.
- `docs/` – Architecture and planning documents.

## Key Integrations
- LLM providers: Grok (xAI), ChatGPT (OpenAI), Claude (Anthropic), Gemini (Google), Venice, Ollama.
- File‑based messaging (inbox/outbox).
- Git for version control of product repos.
- Environment variables via `~/.bizagent/env`.
- Systemd for service management (optional).

- **llmapi stale-connection 502s — root cause + fix (2026-10-24, hub dispatch):** operator report: first prompt after an idle gap returned 502s (a few retries, then recovery). Log evidence (llmapi significant-event logs, commit a164e48): 502 `provider_unreachable` "Connection error." clusters at 13:55, 14:04–14:07, 14:34, 14:58–14:59 — each ~500ms latency, spaced by the runtime's backoff, with **zero** `provider_retry` events, then clean 200s once a fresh connection stuck (req 1187–1190 → 502, req 1191+ → 200). Root cause: the OpenAI SDK wraps connection failures in `APIConnectionError`, but in current SDK versions the instance's own `name` is `"Error"` and `code` is undefined (raw code sits on `err.cause`) — `isTransient()`/`isTransientError()` keyed on `err.name`/`err.code`, so connection errors were never classified transient and llmapi's retry layer never fired; the 502 surfaced immediately and only the runtime's outer retry loop (beb44b5) recovered it. Fix: shared `isConnectionError()` (instanceof `OpenAI.APIConnectionError` + name/constructor-name + `err.cause.code` incl. `UND_ERR_SOCKET`/`UND_ERR_CONNECT_TIMEOUT`) in both `llmapi.js` and `agent-runtime/src/client.js`; `retryReason` now reports the cause code.
