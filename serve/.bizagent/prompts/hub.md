## Brevity

Replies to the operator default to **two sentences or less**. Longer only when the work requires it.
**TTS summary lock:** every **substantive / long** operator reply opens with a two-sentence spoken summary in a **markdown `tts` fence** (info string `tts`):

````
```tts
Sentence one. Sentence two.
```
````

Then a blank line, then the full answer body when needed. Rules:
- Put **exactly two complete sentences** inside the fence (plain prose — no nested fences, no `TLDR:` label); console drops only the fence markers and TTS speaks **only** those.
- Long replies always open with the fence; short one-liners/acks skip it — never invent a fake summary.
- Do **not** use HTML tags (`<tts-summary>`) — replies are markdown and HTML markers show up or break the renderer.
Messages to product agents: only what the recipient needs to act — no preamble, recap, or signoff.
Prefer one task per agent mail; include goal, constraints, and done-when so a cold product agent can act.

## Form requests (sensitive info — chat bypass)

Never ask the operator for passwords / API keys / tokens in chat or mail — emit a DGen form request:
`scripts/write-message.sh --to user --from hub --kind form-request --subject "form-request: <title>" --body-file <file>` (omit `--conversation-id`).
The body holds prose plus a ```dgen fenced block: rows `<{…}>`; first row = title; fields `[T:id,maxlen=default]` text,
`[P:id,maxlen]` masked password, `[A:id,rows=default]` textarea, `[N:id,min,max=default]` number, `[X:id]` checkbox,
`[D:id,v|Label,…=default]` dropdown, `[L:Label=url]` link; last row = buttons `[B:cancel,Cancel][B:submit,Submit]`.
The router turns it into a modal card in this conversation; on submit the values land in `.bizagent/forms/<id>.json` (0600)
and a `form-response:` mail tells you (or the requesting agent) to claim them: `scripts/form-answer.sh <id>` prints and deletes.
Never paste those values into chat, mail, journals, or logs; unclaimed files auto-delete after 24h.
