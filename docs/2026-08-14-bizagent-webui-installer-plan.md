# BizAgent Web UI + Installer Plan (APPROVED)

Date: 2026-08-14
Status: Approved by operator — delegated to Agent BA for implementation.

## Scope

Four changes across the BizAgent web UI and installer. No implementation until this
plan is approved.

---

## 1. Web UI — Live "thinking" log

**Goal:** While the hub is working, show the **hub's** thinking streaming on the page
instead of a static "working please wait" message.

**Behavior:**
- The thinking text streams into the same area that currently shows "working please wait".
- It scrolls live as new lines arrive.
- When the response is ready, the thinking is replaced by the response (the thinking
  disappears).

**Scope — hub thinking only (operator confirmed):** The chat is a direct line to the
hub (PTL). Product agents work asynchronously in their own repos and report back via
mail, so the chat only ever shows the **hub's** thinking — never a product agent's.
There is no collision because there is always exactly one stream.

**Future option (not built now):** Viewing a specific product agent's thinking while it
works (e.g. a per-product status/log view in the UI, or streaming that agent's steps
into a panel). Operator chose to defer this; design should keep it as a clean future
extension rather than precluding it.

**Notes:** This is the "easiest first" option the operator picked. No separate log
panel, no auto-scroll toggle — just stream-in-place then swap.

---

## 2. Web UI — "Agents" list → "Products" list

**Goal:** Rename and re-layout the list.

**Behavior:**
- Header changes from "Agents" to "Products".
- Each row shows **three lines**:
  1. **Product name** on top (large font).
  2. **Agent name** in the middle (smaller font).
  3. **Model** beneath (smallest / supporting line).
- No other fields added for now.

**New addition (from operator):** Add an **interrupt / stop** control for a runaway
agent.
- **Pressing Escape stops the thinking immediately** — a hard stop (like most CLIs).
- This cancels the in-flight turn and halts the agent that has gone off the rails.
- No separate "Stop" button and no clickable status light — Escape is the interrupt
  control.

---

## 3. Installer — API key at install time

**Goal:** Capture the LLM API key during installation.

**Behavior:**
- At the step where the user chooses a CLI, the installer also asks for the API key.
- The key is stored in `.agents/env`.
- No special validation beyond non-empty (operator confirmed no prefix requirement).
- The LLM is needed to complete the installation, so the key is required at that point.
- **Warn the user:** if the API key is entered incorrectly, they will **not** be able to
  complete the installation. Surface this warning clearly at the prompt.
- **Validate the key:** after entry, send a tiny "hello" prompt to the LLM to confirm the
  key works before proceeding. If it fails, prompt again — keeps the install error-free.

---

## 4. Preview — clickable link (PHP/HTML)

**Goal:** Let the operator preview built pages.

**Behavior:**
- When a page is built (e.g., a squeeze page), the agent hands back a **clickable link**
  that opens the rendered page in a **new window/tab**.
- No embedded iframe, no live-reload — just a link to the rendered page.

---

## Open items / decisions
